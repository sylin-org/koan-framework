# DAC-12 — Independently certify SQLite as a gold reference

| Field | Value |
|---|---|
| Phase / kind | gold / certification |
| Depends on | DAC-23 |
| Unlocks | DAC-30 (with DAC-22) |
| Primer scope | complete frozen SQLite manifest |
| Production writes | forbidden |
| Owner | Independent certification |

## Meaningful outcome

“Relational gold reference” is backed by a fresh execution of every applicable obligation, not implementation status.

## Required work

1. Reproduce DAC-23's integrated checkpoint and dynamically re-inventory surfaces, claims, registrations, types,
   execution paths, and retirement absence.
2. Run strict Forge and every applicable SQLite cell across all four source-policy postures from clean databases.
3. Re-run native plans/dispatch counts, faults, cancellation, lifecycle, restart/durability, soak, bounds, and
   provider-relative cold/warm performance evidence.
4. Reconcile examples, facts, health, errors, docs, and product claim inputs to the executable manifest.
5. Adversarially review policy bypass, extra materialization, duplicate ownership, hidden fallback, false optimization,
   unbounded state, copied structure, bridges, shadow registration, and unreachable helpers.
6. Change evidence/truth only. A failure returns as a contract-linked black-box case to DAC-11; DAC-13, DAC-23, and
   both certifications rerun. Never repair production in certification or restore retired code.

## Definition of done

- [ ] Independent packet verdict PASS with zero Observed RED/DEFER.
- [ ] Source identity exactly matches DAC-22's DAC-23 checkpoint.
- [ ] Every decline has corrective negative proof.
- [ ] Empty-root, architecture, retirement-absence, and one-execution-path verdicts pass.
- [ ] SQLite is recorded as earned relational gold; public promotion remains DAC-90 work.

## Stop conditions

Any production edit, skipped required cell, unexplained regression, missing surface, legacy/dead/bridge path,
architecture concern, or packet mismatch blocks certification.
