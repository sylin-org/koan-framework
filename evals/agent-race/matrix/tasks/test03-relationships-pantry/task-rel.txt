Build a small web application for a cooking club that manages recipes and ingredients.

Requirements:
- REST API (JSON) for recipes at /api/recipes and for ingredients at /api/ingredients.
- A recipe has: id (string), title (string), instructions (string), and ingredient lines. Each line references an ingredient by name and carries a quantity and a unit.
- An ingredient is a first-class entity with id (= its name, lowercase) and name. Ingredients are shared across recipes: "milk" is one ingredient that every recipe line referencing "milk" points at.
- A line without a quantity means "some" — presence matters, amount does not (salt is typically such an ingredient).
- Quantities may be expressed in different units. Conversion table: glass = 240 ml, tbsp = 15 ml, piece = 1. Comparisons and filters must work correctly across units (2 glasses of milk = 480 ml, and must satisfy a "more than 300 ml" filter).
- Endpoints that must exist:
  - GET /api/ingredients lists the ingredients; POST /api/ingredients creates one.
  - Standard CRUD for recipes: GET/POST/PUT/DELETE /api/recipes and /api/recipes/{id}. GET responses include the recipe's ingredient lines.
  - GET /api/ingredients/{name}/usage-count -> exactly {"count": N} where N is the number of recipes referencing that ingredient.
  - GET /api/recipes/using?ingredient={name}&minQuantity={q}&unit={u} -> a JSON array of recipe objects (recipes using at least that canonical amount of the ingredient; the conversion table applies).
  - GET /api/stats -> a JSON object that includes "recipesWithMoreThan10Ingredients": the count of recipes with more than 10 ingredient lines.
  - POST /api/recipes/match with {"pantry":[{"name":"milk","quantity":480,"unit":"ml"},{"name":"salt"}]} -> a JSON array ordered best-first: fully-covered recipes first, then by fewest missing ingredients. Every element is exactly {"title": string, "missingCount": number, "missing": [string array of missing ingredient names]}. A pantry item without a quantity matches any amount of that ingredient.
  - GET /api/recipes/search?q=<phrase> -> recipes ranked by semantic similarity to the phrase, not keyword overlap. Embeddings come from the local Ollama model "nomic-embed-text" at http://localhost:11434. No cloud services.
- The application must start with `dotnet run` from the folder containing the .csproj file and listen on http://localhost:5099.
- Data must persist to a SQLite database file inside the project folder and survive an application restart.
- Target framework: net10.0.

Constraints:
- Create your project in the current directory (it is empty).
- Work only inside the current directory.
- Everything must build and run offline except NuGet package restores.
- No authentication, no multi-tenancy, no uploads, no frontend.
- Do not modify anything outside the current directory.

Definition of success: after `dotnet run`, a client can create and list ingredients, create recipes whose lines reference them, read recipes back with their lines, the usage-count, "using" filter, and stats endpoints return correct numbers across units, the pantry match returns fully-covered recipes first with exact missing lists, the semantic search returns relevant recipes for phrases that share no words with them, and the data survives a restart.
